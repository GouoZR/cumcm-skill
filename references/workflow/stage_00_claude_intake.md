# Stage 0 — 题面解析与初始框架

## 目标

把用户已放入工作区的题面和附件转成可供建模的事实基础。默认自动扫描，不询问队伍人数、成员擅长、截止时间、运行模式或已确定的题号。

## 执行

1. 清点 `input/` 中的题面、附件、数据字典和说明文件；记录格式、大小、编码、表字段和缺失情况。
2. 将题目拆成子问题、显式要求、约束、评价目标、最终需回答的量和交付物。
3. 区分题面事实、合理推断和待验证事项，不编造缺失条件。
4. 输出初始问题结构、候选建模方向和风险，但不冻结正式模型。
5. 按下节写入初始时间预算与降级阶梯，作为后续阶段的进度基线。
6. 更新 artifact manifest，并生成交接单给 Codex Stage 1。

只有以下情况可以提一个阻断性问题：没有任何题面；存在多个无法判定的题目版本；关键附件无法读取且没有可替代输入。

## 时间预算与降级阶梯

CUMCM 是连续限时赛，具体起止时刻以当届官方通知为准；实现和写作阶段最容易挤压提交前的核对时间。Stage 0 必须在 `artifacts/problem_analysis.md` 中写入一节「时间预算」：

- 若用户已说明截止时间，按真实剩余时间倒推；否则优先依据已核验的当届官方起止时刻和当前时间计算。无法可靠确定时，只给出分阶段 provisional 比例并标注依据，不为此提阻断性问题，也不得把赛事总时长直接当作剩余时间；
- 预留写作、跨文件核对、排版和上传缓冲，不把预算排满到截止时刻；
- 记录降级阶梯，明确时间不足时的取舍顺序（先降问题规模、近似求解或减少可选实验，最后才削减子问题覆盖面）；
- 逐问覆盖完整性、结果可复现性和引用真实性不在可削减项内。

该预算是进度基线而非硬约束。Stage 2/4 发现实际耗时显著偏离时，在交接单「未解决问题」中说明偏差和已采用的降级措施，让 Codex 在审计时知道哪些取舍是有意为之。

## 验收

- 每个子问题有输入、输出、约束和评价目标；
- 数据清单可追溯到原文件；
- 未把候选模型写成既定方案；
- 已写入时间预算与降级阶梯，并标明是实测倒推还是 provisional；
- 没有为启动而索取非必要团队信息。
