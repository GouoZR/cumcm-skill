# CUMCM 分题型质量门

本文件把通用“模型合理、结果可信”拆成可执行检查。它不是算法清单，也不是官方评分标准。Stage 1 按实际题型选择适用项写入 `artifacts/quality_contract.json`，Stage 2 执行，Stage 3 独立审计，Stage 5 检查论文是否越过证据边界。

## 一、所有赛题共同的六道门

### 1. 题意翻译门

- 明确分析单位、索引集合、输入、输出和题面真正要求回答的量；
- 写清时间、空间、对象、分组和样本范围；
- 区分“模型内部代理指标”与“题目最终评价指标”；
- 对求和、均值、并集、最大值、归一化、加权和去重规则给出明确口径。

### 2. 数据口径门

- 原始数据、清洗数据、训练数据、验证数据和最终结果具有可追踪关系；
- 缺失、异常、重复、单位转换和人工修订均保留日志；
- 下游问题复用上游结果时记录版本、单位和误差传播方式；
- 不得因清洗或筛选提前使用测试集、未来信息或目标标签。

### 3. 基线与独立证据门

正式模型之外至少保留一种独立证据：朴素基线、人工小算例、小规模精确解、替代求解器、留出集、文献量级、守恒关系或不复用生产函数的独立复算。若没有合理基线，必须说明原因并采用其他证据。

### 4. 不变量与反例门

每个子问题至少给出一条模型应始终满足的性质，并将其变成测试或明确复核步骤。优先选择：

- 量纲一致、边界值、守恒关系和可行性；
- 单调性、对称性、置换不变性、上下界；
- 重复样本/对象、极端输入、空集和退化情形；
- 聚合前后分解恒等式；
- 可人工算出的微型反例。

### 5. 保真度与离散化门

使用采样、网格、步长、聚类、降维、线性化、代表点或代理模型时，说明：

- 近似替代了什么真实对象；
- 主结果采用哪个保真度层级；
- 候选筛选与最终复核是否使用不同层级；
- 加密采样、缩小步长或提高模型保真度后，结论是否收敛；
- 不能收敛时的误差或适用边界。

### 6. 结论作用域门

结论只能覆盖证据实际验证的题目、数据、时间、样本、参数范围和随机性水平。局部扰动不得写成全局稳健，单因素分析不得证明无交互，单次随机运行不得证明算法稳定，相关性不得写成因果性。

## 二、分题型最低验证集

### A. 数据处理与统计描述

至少检查：

- 原始记录数、清洗后记录数及每一步增减原因；
- 缺失机制和填补方法是否改变分布或下游结论；
- 异常值规则是否由题意、统计依据或业务边界支持；
- 单位、编码、时间顺序和重复记录；
- 描述性结论是否把样本规律外推为总体规律。

### B. 预测与时间序列

至少检查：

- 数据切分先于标准化、特征选择、填补和调参，防止泄漏；
- 时间序列使用滚动或时间顺序验证，不随机打乱未来信息；
- 与均值、持续性、线性模型等朴素基线比较；
- 报告总体误差之外的分组误差、残差或区间覆盖；
- 对外推区间、结构突变和样本外使用给出边界。

### C. 分类、识别与聚类

至少检查：

- 类别不平衡、阈值选择和评价指标适配；
- 混淆矩阵以及 macro/micro/weighted 口径；
- 聚类结果的稳定性、可解释性和簇数依据；
- 训练集拟合、验证集评价和最终部署阈值不混用；
- 标签定义、人工标注和弱标签误差得到说明。

### D. 综合评价、排序与权重

至少检查：

- 指标正负向、无量纲化和极端值处理；
- 权重来源与模型目标一致，主客观权重不重复表达同一信息；
- 排名对归一化方法、权重扰动和样本增删的稳定性；
- 报告分数差距，而不只报告名次；
- 不把数学排序直接写成现实因果或政策结论。

### E. 优化、调度与决策

至少检查：

- 所有题面约束均映射为代码中的可行性检查；
- 目标函数明确计量对象、重复计数、归一化和多目标权衡；
- 小规模可精确求解时给出枚举、动态规划、MILP/CP-SAT 或上下界对照；
- 启发式报告多次运行、预算、收敛和最好/均值/最坏结果；
- 输出目标值分解、约束违反量和方案可执行性，而不只给最优参数。

### F. 仿真、随机过程与机理模型

至少检查：

- 初值、边界条件、量纲、守恒或平衡关系；
- 时间步长、网格密度、仿真时长和热身期的收敛性；
- 随机种子、多次重复、置信区间或分位数；
- 参数可辨识性和校准数据是否足够；
- 模型输出与现实量级、极限情形或独立公式互校。

### G. 网络、空间与时空问题

至少检查：

- 坐标系、距离、邻接、边界和时间同步定义；
- 点、区域、路径、网络或连续场之间的简化是否经过保真度检查；
- 空间分辨率、时间分辨率和搜索范围的收敛；
- 多对象重叠、覆盖、连通和重复计数规则；
- 地图或轨迹图与数值结果使用同一坐标和单位。

## 三、Stage 3 的独立审计要求

1. 主 Agent 至少选一个决定性结果，从原始决策、预测或中间结果重新构造；不得只再次调用正式模型的总目标函数。
2. 对 `quality_contract.json` 中每条不变量检查其测试、日志或人工复核证据。
3. 核对 `results/result_registry.json` 的每个 primary 指标能否定位到真实结果文件，并与图表和候选结论一致。
4. 发现正式模型和质量契约冲突时，以题面和已确认的模型定义为准，退回 Stage 2；不得通过修改审计口径迁就现有结果。
5. 若某类最低验证不适用，审计报告必须写明不适用理由，不得静默跳过。

## 四、Stage 5 的表述约束

| 已有证据 | 可以写 | 不可以直接写 |
|---|---|---|
| 单个数据集或单一时段 | 在该数据/时段内表现为 | 普遍适用于所有地区和时期 |
| 单因素扰动 | 在给定单因素范围内稳定 | 参数之间无交互、全局稳健 |
| 单个随机种子 | 本次运行得到 | 算法稳定、结果可重复 |
| 训练集或拟合优度 | 对样本拟合较好 | 预测能力强、泛化良好 |
| 相关分析 | 与……相关 | 导致、促进、抑制 |
| 代表点或低保真模型 | 在该近似口径下 | 对完整对象误差很小 |
| 启发式最好值 | 当前预算下获得最好可行解 | 全局最优解 |

## 五、使用原则

- 质量门服务于题意与证据，不要求每题堆满所有检验；
- 选择最能击中模型主要失效风险的少量检查；
- 简单且可核验的模型优先于复杂但无法验证的模型；
- 不能通过增加算法名称、图表数量或篇幅替代数学正确性；
- 当届官方规则、题面和附件始终高于历史论文与经验模式。
